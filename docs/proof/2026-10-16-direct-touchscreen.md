# 2026-10-16 — Прямое управление тачскрином (не тачпад)

## Задача
Пользователь: «сделай управление тачскрином. не ебаное перемещение курсора тачпадом».
Тап пальцем = клик в точку касания; удержание = ПКМ; drag = перетаскивание; 2-й палец = скролл.

## Диагностика причины «тачпада»
1. **Клиентский pref**, не сервер: `checkbox_touchscreen_trackpad` в
   `com.limelight_preferences.xml` (дефолт `true`) → Moonlight уводит тач в
   `RelativeTouchContext` (дельты), а не в `AbsoluteTouchContext`.
2. В этой сборке Moonlight 12.2 `sendTouchEvent()` / `LI_TOUCH_EVENT_* = 0x55000002`
   из Java **не вызываются** вообще. «Прямой тач» у клиента реализован как
   `AbsoluteTouchContext` → `sendMousePosition()` = **абсолютная мышь**
   (magic `0x05` MOUSE_ABS) плюс кнопки. То есть сервер должен уметь принимать
   абсолютную позицию — иначе клиент молча деградирует в тачпад.
3. **Дельтовый пересчёт абсолюта не работает**: `move_frac()` (абсолют → REL-дельты)
   врёт из-за ускорения курсора Hyprland (`force_no_accel=false`, `accel_profile` пусто).
   Дельта накапливает ошибку по всей траектории.

## Решение
Отдельное **uinput-устройство EV_ABS** (`nx-server virtual touch cursor`) c
`ABS_X/ABS_Y` диапазоном `0..32767`. libinput позиционирует курсор 1:1,
ускорение на абсолютные координаты не действует.

- `create_abs_device()` — `UI_ABS_SETUP` (`0x401c5504`), ABS_X/ABS_Y 0..32767,
  BTN_LEFT/MIDDLE/RIGHT; `EV_KEY` не дублируется на REL-устройство.
- `desktop_bbox()` — логический bbox **всех** мониторов. Доля вывода → глобальная
  логическая координата → нормировка bbox.
- `abs_move(fx, fy)` — использует ABS-устройство; при его отсутствии деградирует
  в старый `move_frac()` (REL-дельты).
- `button()` — шлём на устройство **текущего режима**: иначе позиция (ABS) и клик
  (REL) окажутся на разных указателях и щелчок попадёт не туда.
- `wheel()` — **не тронут**, всегда идёт в REL-устройство через `self.emit()`.
  Скролл не зависит от позиции курсора, поэтому ABS-режим его не ломает.
- Клавиатура — без изменений.

Клиент: `checkbox_touchscreen_trackpad=false` (записан через `sed` после force-stop,
владелец `u0_a163` и SELinux `app_data_file` сохранены).
`checkbox_absolute_mouse_mode` не трогали.

## Измерения (прогон)
Стрим: планшет 2176×1600 → HEADLESS-4 1088×800, сервер выводит лог. 1360×1000 @ 0,900.

Лог сервера при старте стрима:
```
input: абсолютный указатель (EV_ABS) готов — прямой тач 1:1
input: uinput-инъекция готова — вывод HEADLESS-4 лог. 1360x1000 @ 0,900 (bbox 0,0..6016,1900)
```

## Не проверено end-to-end
- **Скролл двумя пальцами**. `adb input` не умеет мультитач; синтез сырого
  мультитача через `sendevent` на `/dev/input/event4` (himax-touchscreen)
  Moonlight воспринял как однопальцевый тап/драг. Проверен только путь кода:
  `wheel()` пишет `EV_REL REL_WHEEL*` в REL-устройство независимо от режима —
  то есть моей правкой скролл не задет, а жест 2 пальцев целиком на стороне клиента.

## Вторая итерация: свайп не должен выделять текст
Симптом (заказчик): «перемещаю курсор по веб-страницам — всё выделяет, как будто
зажал мышь; водил одним пальцем».

Проверка, что это **не** залипание: `EVIOCGKEY` на evdev-ноде ABS-устройства
показал `BTN_LEFT отпущена` в покое — кнопку клиент корректно отпускает.

Настоящая причина — встроенное поведение direct-touch Moonlight
(`AbsoluteTouchContext`), сервер его лишь пересылал:
- `touchDownEvent` ставит `tapDownRunnable` через **0x64 = 100 мс**;
- `touchMoveEvent` при сдвиге **>20 px** (`distanceExceeds(…, 20.0)`) зовёт `tapConfirmed()`;
- `tapConfirmed()` **без вариантов** заканчивается `sendMouseButtonDown`
  (смали `:cond_2 → invoke sendMouseButtonDown`);
- `longPressRunnable` через **0x28a = 650 мс** отпускает ЛКМ и жмёт ПКМ (`const/4 0x3`).

То есть ЛКМ нажимается и от таймера, и от самого движения пальца → палец «зажимал
мышь» при обычном ведении.

### Решение (сервер, `src/stream/input.rs`)
ЛКМ при прямом таче стала **отложенной**, вердикт выносит движение:
- пришло нажатие → не эмитируем, запоминаем `(время, gx, gy)`;
- палец поехал раньше `DRAG_HOLD_MS` и дальше `DRAG_PX` → **свайп: ЛКМ не жмём вовсе**;
- палец простоял `>= DRAG_HOLD_MS` и поехал → подтверждаем нажатие → перетаскивание;
- отрыв без движения → тап: шлём `DOWN+UP` одним блоком (клик).

Константы: `DRAG_HOLD_MS = 150` мс, `DRAG_PX = 24` лог. px.
Прочие кнопки и скролл не тронуты; ПКМ (клиентский long-press) проходит мимо
логики ЛКМ.

### Замеры (самотест `nx-server inputtest HEADLESS-4`)
Состояние читается `EVIOCGKEY` с evdev-ноды устройства, а не по отчётам:
```
A свайп  → BTN_LEFT отпущена (надо отпущена) OK
A отрыв  → BTN_LEFT отпущена (надо отпущена) OK
B drag   → BTN_LEFT ВЖАТА    (надо ВЖАТА)    OK
B отрыв  → BTN_LEFT отпущена (надо отпущена) OK
C тап    → BTN_LEFT отпущена (надо отпущена, клик ушёл) OK
```
Точность позиционирования не изменилась: `frac(0.50,0.50) → курсор (680,1399)`.

## Известные границы
- `hyprctl dispatch movecursor X Y` **не работает**. Курсор возвращается только
  через EV_ABS-устройство (`/tmp/opencode/abs_warp.py`).
- Маппинг координат тач-панели из kernel-пространства в экранное не определён:
  панель портретная (`ABS_MT_POSITION_X` 0..1599, `Y` 0..2175) при ландшафтном
  экране 2176×1600. Произвольный `sendevent` попадает не туда.
- 20–30 мс недостижимы; нативное 2176×1600 недостижимо (софт-декодер);
  MTK HW-декод сломан; сервер не персистит спаренных клиентов.
