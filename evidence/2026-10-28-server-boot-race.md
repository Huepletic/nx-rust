# 2026-10-28: стрим не стартует — гонка автостарта сервера с композитором

## Симптом

С утра 2026-10-28 стрим не поднимался ни вручную, ни автоматикой watchdog'а:

- рукопожатие RTSP доходило до ANNOUNCE (клиент присылал рабочие параметры
  `1088x800@60, encryption=1`) и обрывалось на `probe_output_size`;
- в логе nx-server последней строкой сессии оставалось
  `rtsp[192.168.8.89:...]: probe_output_size` — ошибка без корня;
- сервер при этом был жив: `curl https://.../serverinfo` → HTTP 200 за 58 мс,
  слушал 48984/48989, потоки в epoll;
- Moonlight после нескольких неудач кэшировал «archpizdetc - Offline» и по
  тайлу открывал алерт (Test Network Connection / View Details / Delete PC)
  вместо подключения.

## Что мерili

```
$ ps -o lstart= -p 744          # живой на тот момент nx-server
Wed Oct 28 13:26:22 2026
$ ps -o lstart= -p $(pgrep -x Hyprland)
Wed Oct 28 13:26:24 2026

$ tr '\0' '\n' < /proc/744/environ | grep -E 'WAYLAND|DISPLAY|HYPRLAND'
WAYLAND_DISPLAY=
DISPLAY=
HYPRLAND_INSTANCE_SIGNATURE=
```

Сервер (pid 744) стартовал на **2 секунды раньше** композитора и получил
пустое окружение Wayland.

## Корень

`launch_nx.sh` при старте определяет `WAYLAND_DISPLAY` (из `NX_WAYLAND_DISPLAY`
или первым существующим сокетом `wayland-*`); если сокета ещё нет — раньше
скрипт делал `unset WAYLAND_DISPLAY` и запускал сервер «слепым».

Окружение фиксируется на `exec` и больше не меняется. Найденный сокет
композитора через 2 с после старта серверу уже недоступен — до ручного
рестарта **каждый** стрим падал в `wlr_probe_output_size` с ошибкой
«нет WAYLAND_DISPLAY» (цепочка anyhow печаталась только верхним звеном
`probe_output_size`, корень был не виден).

То есть после любого ребута хоста/перезапуска сессии автостарт поднимал
сервер слепым, и стримы работали только если кто-то вручную перезапускал
сервер после появления сессии.

## Попутные находки (те же симптомы, отдельные причины)

1. **Watchdog рвал рукопожатие.** Старый `reconnect_stream` через 4-6 с после
   тапа по хосту недовидел ffmpeg и делал monkey-relaunch Limelight, убивая
   соединение на середине (доказано логом: ANNOUNCE в 13:29:08, клиент
   обратно в списке приложений через 6 с).
2. **Кэш «offline» в Moonlight.** После окна сломанного USB-канала (14:00-14:12)
   Moonlight пометил хост offline и перестал его опрашивать; ни BACK, ни
   pull-to-refresh кэш не сбрасывали — помогал только cold-restart клиента
   (`am force-stop com.limelight`, разрешён табу при отсутствии стрима).
3. **Два экземпляра wireplumber** (pid 641 и 2196, ~50% CPU каждый) делят
   D-Bus имя ReserveDevice1 — та же спираль, что 2026-10-21. Рестарт из
   watchdog'а падает rc=1. Требует отдельного разбора (кто второй запускает).

## Что исправлено

- `launch_nx.sh`: если Wayland-сокета нет, а это не X11 — ждём появления
  сокета (glob `wayland-*`, до 90 с, шаг 2 с) вместо `unset`. Покрывает и
  устаревший `NX_WAYLAND_DISPLAY` (несуществующее имя → пересылка по факту).
- `src/stream/rtsp.rs`: ошибка обработки соединения печатается `{:#}`
  (вся цепочка anyhow), чтобы корень («нет WAYLAND_DISPLAY») был виден.
- `watchdog.py` (`reconnect_stream`): после тапа по хосту/Desktop — ожидание
  старта до ~45 с без relaunch; незнакомое состояние — ожидание, не relaunch;
  offline-алерт — BACK, затем pull-to-refresh, при залипании кэша —
  cold-restart Limelight; тайл хоста матчится по началу строки
  («archpizdetc - Offline»).

## Проверено

- после рестарта через `launch_nx.sh` у нового pid окружение
  `WAYLAND_DISPLAY=wayland-1`, `DISPLAY=:0`, serverinfo 200;
- автономная цепочка watchdog до живого стрима — см. вывод сессии ниже.

## Не проверено

- suspend планшета на полке (`suspend_stats/success > 0`) — требует
  отсоединения кабеля на 2-3 ч.
- происхождение второго экземпляра wireplumber.
