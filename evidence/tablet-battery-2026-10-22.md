# Батарея планшета: «не заряжается, пока не используется» + «жрёт батарею»

Дата: 2026-10-22. Планшет: Treble GSI (Android 11, userdebug, `adb root` доступен),
MTK mt6370 + внешний зарядчик SGM41513, ядро `4.14.186-00087-gec057bcf0ff4-dirty`.
Подключение к хосту: USB-A порт (`1-3`, RNDIS+adb), адрес планшета 192.168.8.89.

## Итог одной строкой

**Планшет физически не может заряжаться от нашего USB-A порта: порт даёт 500 мА,
а драйвер зарядки планшета программирует ток заряда ровно на весь бюджет порта
(ICHG = 500 мА) — места не остаётся, и драйвер выключает заряд (CHG_EN = 0).
От сетевой зарядки планшет берёт 2 А и заряжается нормально.** А «жрёт батарею»
в простое — висящий в фоне Limelight (~150 мА) — это уже починено модулем.

## 1. Железо и драйвер: что именно происходит

Регистры зарядчика (dmesg, `mt6370_pmu_charger`):

```
ICHG = 500mA, AICR = 500mA, MIVR = 4400mV, IEOC = 250mA, CV = 4350mV
VSYS = 4350mV, VBAT = 4135mV, IBAT = 0mA, IBUS = 150-400mA, VBUS = 4900-4975mV
CHG_EN = 0, CHG_STATUS = ready, CHG_STAT = 0x80
```

и лог решения драйвера:

```
mtk_dual_switch_charging_run [6]
mtk_pe_check_charger: stop, PE+ is disabled
sgm41513_enable_charging: disable charge
sgm41513_enable_chip: enable_chip: false
```

Т.е. питание есть (VBUS 4.95 В), батарея не полная (4.135 В при CV 4.35 В),
температура в норме (28 °C), а заряд выключен **решением драйвера**.

Параметры из Device Tree (`/proc/device-tree/charger`, значения big-endian):

| свойство | значение | смысл |
|---|---|---|
| `usb_charger_current` | 500 000 мкА | ток от обычного USB-порта |
| `charging_host_charger_current` | 1 500 000 мкА | ток от host-порта с PE+ |
| `ac_charger_current` / `ac_charger_input_current` | 2 000 000 мкА | сетевая зарядка |
| `ta_ac_charger_current` | 3 000 000 мкА | Type-A адаптер |
| `non_std_ac_charger_current` | 2 000 000 мкА | нестандартный сетевой |
| `enable_type_c` / `enable_pe_plus` | есть | Type-C/PE+ поддержаны |
| `battery_cv` | 4 350 000 мкВ | до какого напряжения заряжать |
| `min_charger_voltage` | 4 600 000 мкВ | минимальное напряжение на входе |

Узел `lk_charger` (классические таблицы MTK bmt-зарядки):
`usb_charger_current=500000`, `ac_charger_current=2000000`, `ta_ac_charger_current=3000000`.

**Логика драйвера:** источник определён как USB-порт ПК (DCD: `mt6370_get_tchg: tchg = 32`),
поэтому AICR = 500 мА, и ток заряда ICHG тоже 500 мА — то есть весь бюджет порта.
Планшет при этом сам потребляет 100-400 мА → сумма превышает бюджет → заряд выключен.
Проверено экспериментально: при снижении собственного потребления до ~100 мА
(`am force-stop com.limelight` + `dumpsys deviceidle force-idle`) CHG_EN остаётся 0 —
места не появится, пока ICHG = AICR.

## 2. Почему «не используется — не заряжается», а «используется — заряжается»

По нашим замерам заряд **не идёт ни в одном состоянии**: экран выключен, экран
включён (`input keyevent KEYCODE_POWER`), приложение в фоне, приложение убито —
`charge_counter` неизменно (6 258 000 мА·ч), `status: Not charging`.

Значит «заряжается при использовании» = в этот момент был подключён сетевой
зарядник (2 А по таблице DT) либо другое питание. От нашего порта — не заряжается
никогда.

## 3. «Что-то жрёт батарею» — три источника, все на нашей стороне

### 3.1 Висящий в фоне Limelight (~150 мА)

Замер по IBUS (ток с порта хоста) при выключенном экране и выключенном WiFi:

| состояние | IBUS |
|---|---|
| фон: экран выкл, WiFi выкл, doze | 300 мА |
| + `dumpsys deviceidle force-idle` | 250 мА |
| + `am force-stop com.limelight` | **100 мА** |

То есть приложение в фоне ест ~150 мА — столько же, сколько вся остальная система.

### 3.2 Шторм переподключений в watchdog (главный жор)

В логе watchdog с **2026-10-22 01:50** каждые ~6 с:

```
[01:50:04]   стрим: неизвестное состояние UI, возвращаю Limelight
[01:50:11]   стрим: неизвестное состояние UI, возвращаю Limelight
...
```

5604 сообщения за ночь. Причина: планшет в doze (экран погашен), `ui_dump`
отдаёт шторку уведомлений, watchdog не находит ни «Desktop», ни хоста — и
`_reconnect_stream()` по кругу поднимает Limelight заново (`monkey`), приложение
живёт постоянно, декодер и USB-гаджет не засыпают.

Это и есть «жрёт батарею», причём в масштабе всего ночного простоя.

### 3.3 Рестарт nx-server каждые ~2 минуты

```
[06:55:05] АУДИО-КОНВЕЙЕР МЁРТ (ffmpeg -f pulse нет) — перезапускаю сервер
[06:56:58] ... [07:04:31] ...
```

`client_connected()` проверял наличие `":49002"` в `ss -uan`, но сервер **всегда**
держит UDP-сокет аудио-порта открытым (слушает, а не подключён) — проверка была
всегда истинной, клиента не было, а watchdog каждые 2 минуты ронял сервер.
Наш конвейер при этом не восстанавливался (клиент не подключался).

### 3.4 Планшет не засыпает

Зарядчик будит систему каждые 10 с:

```
mtk_charger_alarm_timer_func: not suspend, wake up charger
```

`deviceidle` остаётся в `mState=ACTIVE`, висит `DOZE_WAKE_LOCK 'DreamManagerService'`,
`mWakefulness=Dozing`. `dumpsys deviceidle force-idle` в модуле **нет намеренно**:
глубокий idle усыпляет сеть RNDIS и может оборвать канал данных стрима.


## 4. Что пробовали и почему не сработало

| способ | результат |
|---|---|
| `echo 200/200000/100 > /sys/devices/platform/charger/chg1_current` | ICHG остался 500 мА |
| `echo 300000 > .../input_current` | AICR остался 500 мА |
| `enable_sc=1`, `sw_jeita`, `sc_ibat_limit` | эффекта нет (SC — ограничитель, не включатель) |
| `Pump_Express` (read-only, `r--r--r--`) | запись невозможна |
| `adb root` + `/dev/charger_ftm` (FTM-интерфейс MTK, ioctl) | перебрали `_IO/_IOR/_IOW/_IOWR('c',0..15)` — все возвращают 0, регистры не меняются |
| снижение потребления до ~100 мА | CHG_EN = 0, места нет (ICHG = AICR) |
| `cmd battery set status 2` | НЕ применяли: это подделка статуса, батарея бы не заряжалась, а пользователь видел бы ложь |
| `setprop sys.usb.config none` и прочее из табу | не трогали |

Вывод: зарядку отключает связка «железо + драйвер планшета» и «бюджет порта хоста».
Ни наша часть конвейера (nx-server, аудио, роутер) тут ни при чём.

## 5. Что сделано: модуль `nx-rust/scripts/tablet_power.py`

Сервис `nx-tablet-power.service` (systemd, работает на хосте, раз в 60 с):

1. **Гасит Limelight**, когда приложение висит в фоне, экран погашен, стрим не
   идёт и это длится дольше 120 с → экономия ~150 мА. Не трогает приложение,
   если оно на экране или клиент на связи (иначе мешал бы watchdog'у, который
   в этот момент переподключает стрим через `monkey -p com.limelight`).
2. **Следит за зарядом**: `charge_counter` (счётчик заряда), `status`,
   `current_now`, `usb/current_max` (бюджет порта как его видит планшет),
   при возможности — регистры зарядчика из dmesg.
3. **Различает состояния**: `CHARGING` / `USB_PORT_TOO_WEAK` (порт ≤ 500 мА) /
   `ON_BATTERY` / `NOT_CHARGING` — и пишет причину человеческим языком.
4. **Поднимает уведомление** (notify-send в сессию пользователя), если планшет
   в простое, не заряжается и батарея ≤ 60 % — с указанием настоящей причины.
5. Состояние — в `/run/tablet_power.json`, лог — в `/var/log/nx-tablet-power.log`
   (не в /tmp: на этом хосте root не может перезаписать файл пользователя,
   `fs.protected_regular`).

Модуль работает без root на планшете: SELinux не пускает `shell` в `dmesg`,
поэтому опциональные регистровые поля просто остаются пустыми.

### 5.2 Требование пользователя: «в простое заряд ≥ 50 % активного расхода»

**Замер (2026-10-22 07:50-08:00).** `current_now` батареи (мкА, минус = разряд):

| состояние | ток батареи | вывод |
|---|---|---|
| экран выключен, приложение погашено | 0 мА | порт кормит планшет целиком, батарея не тратится |
| экран включён | −243 200 мкА (−243 мА) | активный расход ≈ 240 мА |
| стрим + экран | до −400 мА | активный расход до ~400 мА |

Плюс измерения по дампу зарядчика: IBUS в простое 100-200 мА, с включённым
экраном 400 мА.

**Арифметика:** порт USB-A отдаёт 500 мА. В простое планшет ест ~150 мА →
свободно **~350 мА**. Активный расход ≈ 240-400 мА → половина = **120-200 мА**.
То есть **цель достижима на этом же кабеле и этом же порту** — нужно лишь, чтобы
драйвер разрешил зарядку. Правило 50 % зашито в модуль (`PASSIVE_MIN_RATIO`):
модуль меряет скорость заряда в простое (по `charge_counter`),
запоминает пик активного разряда и поднимает уведомление, если
`passive_charge_ma < 0.5 * peak_discharge_ma`.

## 5.3 Где именно затык (доказано)

1. `ACCDET_CHARGER` на планшете определяет источник как **USB** (порт ПК,
   500 мА) — `mt6370_get_tchg: tchg = 32`.
2. Драйвер зарядки для источника типа USB идёт по ветке PE+ (Pump Express) и,
   не найдя PE+, выключает заряд:
   `mtk_pe_check_charger: stop, PE+ is disabled` → `sgm41513_enable_charging: disable charge`.
3. Таблица токов в DT самого планшета:
   `usb_charger_current = 500 мА` (порт ПК — весь бюджет порта),
   `charging_host_charger_current = 1.5 А` (host-зарядка, т.е. Type-C/PE+),
   `ac_charger_current = 2 А`, `ta_ac_charger_current = 3 А`,
   `enable_type_c = 1`, `enable_pe_plus = 1`.
   То есть **сам планшет рассчитан на зарядку от Type-C/host-источника на 1.5 А**
   — но текущий кабель (USB-A → планшет) даёт «USB-порт ПК», и драйвер
   зарядку выключает.

**Что перепробовано и не сработало:** sysfs `chg1_current`/`chg2_current`/
`input_current`/`enable_sc`/`sw_jeita`/`BN_TestMode`/`BatteryNotify` (ICHG
остаётся 500 мА); `Pump_Express` (read-only); полный перебор ioctl
`/dev/charger_ftm` — 3328 кодов (`_IO/_IOR/_IOW/_IOWR` по всем буквам), ноль
изменений состояния; `cmd battery set status` (подделка статуса, не заряжает).

**Что должно сработать:** источник, который планшет классифицирует как
host/Type-C — тогда включается ветка `charging_host_charger_current` = 1.5 А.
На хосте есть **Type-C порт в режиме source** (`/sys/class/typec/port0`:
`power_role = [source] sink`, `data_role = [host] device`,
`power_operation_mode = default`) — значит кабель **Type-C ↔ Type-C** в этот
порт должен поднять зарядку; модуль это увидит по `usb/current_max` и по
росту `charge_counter` и напишет фактическую скорость.


### 5.1 Правки watchdog (источники жора)

- `client_connected()`: теперь смотрит живое TCP-соединение к control-порту
  49001, а не `:49002` в `ss -uan` (там всегда висит слушающий UDP-сокет) →
  сервер больше не перезапускается каждые 2 минуты.
- `reconnect_stream()`: при погашенном экране планшета переподключение
  откладывается («стрим: экран планшета погашен — переподключение отложено»),
  плюс кулдаун 5 минут между попытками → шторм «неизвестное состояние UI»
  остановлен.

Проверка после правок (07:12-07:20): счётчик «неизвестное состояние UI»
застыл на 5609, в логе watchdog тихо, nx-server жив, RNDIS пингуется
(0.59 мс), планшет в doze с погашенным Limelight (потребление 100-150 мА
вместо 300).

## 6. Что делать пользователю, чтобы планшет реально заряжался

**Шаг 1 (проверка, 30 секунд):** перенести кабель планшета в **Type-C порт
хоста** (`/sys/class/typec/port0`, он в режиме source ✓) кабелем
**Type-C ↔ Type-C**. Тогда планшет увидит Type-C-источник вместо «USB-порта
ПК» и должен перейти на ветку `charging_host_charger_current` = 1.5 А.
Модуль это сразу покажет: `usb/current_max` перестанет быть 500000, а
`charge_counter` начнёт расти (в логе — «заряд: идёт, N мА»).

**Шаг 2 (если шаг 1 не помог):** сетевой зарядник в порт планшета — по DT он
берёт 2 А (AC) / 3 А (Type-A адаптер). Проблема: порт один, и кабель к хосту
(RNDIS) отвалится → связь переезжает на WiFi или на Ethernet-адаптер.

**Помешает** висящий в фоне Limelight — это уже чинится модулем.

**Не требуется** переделывать nx-rust: конвейер стрима к зарядке отношения не
имеет, затык целиком в драйвере зарядки планшета и в типе источника.


## 7. Команды проверки

```bash
# состояние заряда (из модуля)
cat /run/tablet_power.json
sudo tail -f /var/log/nx-tablet-power.log

# что видит планшет
adb shell 'cat /sys/class/power_supply/battery/status \
           /sys/class/power_supply/battery/charge_counter \
           /sys/class/power_supply/usb/current_max'

# регистры зарядчика (нужен adb root)
adb root && adb shell 'dmesg | grep mt6370_dump_register | tail -4'

# потребление планшета
adb root && adb shell 'dmesg | grep -oE "IBUS = [0-9]+mA" | tail -1'

# сервисы
systemctl status nx-tablet-power.service nx-watchdog.service
```
